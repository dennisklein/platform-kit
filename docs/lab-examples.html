Lab configuration examples

Companion to platform-kit design · Example data from raven

Model: one hardware topology, two purposes

A change lab and a digital twin differ in purpose and lifetime, not in hardware. Thus one Topology describes the emulated hardware, and a thin Lab file sets the purpose on top of it.

 state repo                                   generated
 control/inventory/*.yaml ─┐
 control/cabling.yaml      ├──> Topology (machines, BMCs, NICs, networks)
 control/talos/talconfig   ┘          ▲                    ▲
 .pk/emulation.yaml (model → emulator)│                    │
                                      │                    │
                        Lab purpose: twin            Lab purpose: change
                        - follows main               - base ref + change ref
                        - kustomize overlay          - scenario steps + checks
                        - persistent                 - ephemeral, result report
                        - explore, learn, app dev    - gates one change

Each real machine maps to three emulated parts:

PartEmulator
BMCGo Redfish sim with a captured fixture (supermicro-x12, huawei-2288h-v5)
Machineqemu (high fidelity: install, reboot, disks), talos-docker (fast), or none (BMC only)
NICs and networksa bridge per VLAN or segment, routers as FRR containers

Nobody writes the Topology by hand. platform-kit generates it from the desired state, so a twin follows the desired state automatically. Hand changes go in overrides.

1. Emulation profile (hardware model to emulator)

# .pk/emulation.yaml
apiVersion: pk/v1alpha1
kind: EmulationProfile
metadata:
  name: default
spec:
  machines:
    - match: { model: "Supermicro X12*" }
      bmc: { fixture: supermicro-x12 }
      machine: { backend: qemu, cpus: 2, memoryMiB: 8192, firmware: ovmf }
    - match: { model: "Huawei 2288H V5" }
      bmc: { fixture: huawei-2288h-v5 }        # OEM VmmControl path
      machine: { backend: qemu, cpus: 2, memoryMiB: 8192, firmware: ovmf }
  networks:
    bmc:  { vlan: 1034, ipv6: { prefix: fd00:1034::/64, ra: true, dhcpv6: ledger } }
    node: { vlan: 1035, ipv4: { cidr: 10.35.0.0/24 }, ipv6: { prefix: fd00:1035::/64 } }
    ib:   { emulate: false }                    # no HCA in QEMU
  substrate: containerlab
  uplink: nat                                   # never route into the real site

2. Generated topology (read only)

# generated from control/inventory + cabling.yaml + .pk/emulation.yaml
apiVersion: pk/v1alpha1
kind: Topology
metadata:
  name: raven
spec:
  source: { cluster: raven, ref: main }
  machines:
    - name: controller1
      bmc: { fixture: supermicro-x12, mac: from-inventory, network: bmc }
      machine: { backend: qemu, disks: [{ name: system, sizeGiB: 32, serial: from-inventory }] }
      nics: [{ network: node, mac: from-inventory }]
    - name: router1
      bmc: { fixture: huawei-2288h-v5, network: bmc }
      machine: { backend: qemu }
      nics: [{ network: node }]
    # ... controller2, controller3, infra01..03, router2, worker001..005
  overrides: {}

3. Digital twin

# .pk/labs/raven-twin.yaml
apiVersion: pk/v1alpha1
kind: Lab
metadata:
  name: raven-twin
spec:
  purpose: twin
  topology: raven
  follow: { ref: main }                       # re-sync after each merge
  overlay: control/overlays/twin              # kustomize override (next to live, dev)
  substituteFrom: twin-vars                   # Flux postBuild vars: addresses, issuers
  fidelity: scaled                            # replica = all machines
  scale:
    machines: [controller1, router1, worker001]
    backend: talos-docker                     # cheap; qemu for install or disk work
  provision: direct                           # metal = sim BMC → vMedia → Talos install
  host: lab-host-1                            # or: local
  expose: [kube-api, grafana, docs]
  lifetime: persistent
  snapshot: nightly                           # base for change labs

4. Change lab

platform-kit generates it when the lab gate of a path needs a run. A person can also write one for a custom test.

apiVersion: pk/v1alpha1
kind: Lab
metadata:
  name: c-77e1-run-2
spec:
  purpose: change
  topology: raven
  fidelity: replica
  from: raven-twin@snapshot                   # start from the twin snapshot
  base:   { ref: main }
  change: { ref: change/c-77e1-cilium-bgp-peers }
  provision: direct                           # metal for inventory/talos changes
  scenario:
    - name: baseline-healthy
      check: { flux: all-ready, nodes: all-ready }
    - name: apply-change
      gitops: { switchTo: change }
    - name: bgp-up
      check: { bgp: established, timeout: 10m }
    - name: reboot-router
      action: { bmc: { machine: router1, power: ForceRestart } }
    - name: still-healthy
      check: { flux: all-ready, bgp: established, timeout: 15m }
  results:
    collect: [conditions, events, console-logs, flux-status]
    report: html                              # linked from the MR, recorded as Pk-Lab-Run
  lifetime: { ttl: 4h, keepOnFailure: true }
