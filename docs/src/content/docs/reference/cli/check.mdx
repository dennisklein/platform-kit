<CliBadges cmd="check" />

`pk-metal check` tests one BMC before you enroll the machine. It reads only.
The command talks to the BMC directly. It does not use the operator or the cluster.

## Synopsis

<CliSynopsis cmd="check" />

<dl>
  <dt>`<bmc-url>`</dt>
  <dd>The address of the BMC, for example `https://192.0.2.11`. Give one address.</dd>
</dl>

## Flags

<CliFlags cmd="check" />

The password comes from the environment variable `PK_METAL_BMC_PASSWORD`. It is never a flag.

[`--bmc-ca`](cli:check#--bmc-ca) names a PEM file with the CA certificates of your site. The command then accepts only a BMC certificate that chains to one of them.
[`--insecure`](cli:check#--insecure) stops the certificate check. The command then prints a warning: a host on the network path can read the BMC password.

Each request to the BMC must answer in 30 seconds. <kbd>Ctrl</kbd>+<kbd>C</kbd> stops the command at once.

## What it does

1. The command logs in to the BMC with a Redfish session, and deletes the session when it stops. A BMC without sessions gets HTTP Basic authentication.
2. It reads the manager: the vendor and the firmware version.
3. It reads each virtual media slot and the dialect that the slot uses to mount an image.
4. It reads each system: the serial number and the power state.
5. It prints `check: OK (read-only)`.

The session cannot change the BMC. The client refuses all requests that write.

## Examples

<Terminal
title="pk-metal check"
text={`
    $ export PK_METAL_BMC_PASSWORD=...
    $ pk-metal check --user admin https://192.0.2.11
    manager:  Huawei fw 6.72
    media:    CD             dialect=vmm-control
    media:    USBStick       dialect=none
    system:   1 serial=SIMHW2288V5000397 power=On
    check:    OK (read-only)
`}
/>

A slot with `dialect=none` cannot mount an image. This BMC has one slot that can: it is a [](term:one-slot-bmc).

Check a BMC whose certificate comes from the CA of your site:

```sh
pk-metal check --bmc-ca site-ca.pem https://192.0.2.11
```

A BMC in the lab has a self-signed certificate. Add [`--insecure`](cli:check#--insecure) only for such a BMC.

```sh
pk-metal check --insecure https://10.77.0.1:8441
```

## Check the client against real hardware

The test suite has read-only checks for a real BMC. They test that each read answers, that the identity of the machine is there, and that two reads give the same chassis and systems.
The client of the checks refuses each request that writes.

```sh
export PK_METAL_BMC_PASSWORD=...
PK_METAL_HW_URL=https://192.0.2.11 PK_METAL_HW_CA=site-ca.pem mise run test:hardware
```

Without `PK_METAL_HW_CA`, the checks do not verify the BMC certificate. `PK_METAL_HW_USER` sets the user. The default is `admin`.

## Objects

The command reads and writes no object in the cluster.
The operator does the same checks when it reconciles a [](kind:ManagementEndpoint).
