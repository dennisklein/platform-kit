`pk-metal relay` runs on a host that can reach the BMCs, when your workstation cannot.
The BMCs download boot media from the relay, and the relay passes that traffic to [](cli:boot).

## Synopsis

<CliSynopsis cmd="relay" />

The command takes no arguments. It runs until you stop it.

## Flags

<CliFlags cmd="relay" />

## What it does

<dl>
  <dt>Front address</dt>
  <dd>The BMCs connect here to download the image. Put it on the BMC network.</dd>
  <dt>Tunnel address</dt>
  <dd>`pk-metal boot` connects here. It receives the downloads of the BMCs, and its Redfish calls go out to the BMCs through the relay.</dd>
  <dt>Secret</dt>
  <dd>Each connection to the tunnel must prove that it has the shared secret of the relay.</dd>
</dl>

The relay does not decrypt the traffic. TLS ends in `pk-metal boot`.

The relay dials onward only to the targets in [`--allow`](cli:relay#--allow). The default `*:443` lets the relay dial each host on port 443, the port of Redfish. Give a shorter list to limit the relay to your BMC network, for example `--allow 192.0.2.0/24:443`.

### The secret

1. Set `PK_METAL_RELAY_SECRET`, or give a file with [`--secret-file`](cli:relay#--secret-file). Do not give the two.
2. If the file does not exist, the relay writes a new secret there. Only you can read the file.
3. The relay does not replace a file that exists.
4. Give the same secret to `pk-metal boot`.

<Callout type="caution">
Keep the tunnel address on loopback, and connect to it through `ssh -L`. The secret proves who connects. It does not encrypt the tunnel.
</Callout>

The relay is for the first machines of a site. The operator does not use it.

## Examples

On the host that can reach the BMCs:

<Terminal
title="relay host"
text={`
    $ pk-metal relay --front 10.0.0.2:8443 --secret-file ~/.config/pk-metal/relay.secret
    relay: wrote a new secret to /home/admin/.config/pk-metal/relay.secret; give the same secret to pk-metal boot
    relay: front 10.0.0.2:8443 (advertised 10.0.0.2:8443), tunnel 127.0.0.1:9443
`}
/>

On your workstation, open the tunnel and boot a machine through it:

```sh
ssh -N -L 9443:127.0.0.1:9443 admin@relay-host &
pk-metal boot --config clusterconfig/cp-1.yaml --node cp-1 \
  --relay 127.0.0.1:9443 --relay-secret-file relay.secret https://192.0.2.11
```

## Objects

The command reads and writes no object in the cluster. It does not talk to a BMC by itself.

## Exit status

<CliExit cmd="relay" />

The command gives code 1 if it has no secret, or if it cannot listen on one of the two addresses.
