<CliBadges cmd="upgrade" />

`pk-metal upgrade` changes the version in the spec of a [](kind:TalosCluster).
Then it waits for the [](kind:TalosRollout) that the operator proposes, and prints its plan.
Nothing on a machine changes until a person approves that plan.

## Synopsis

<CliSynopsis cmd="upgrade" />

<dl>
  <dt>`talos` or `kubernetes`</dt>
  <dd>What to upgrade.</dd>
  <dt>`<cluster>`</dt>
  <dd>The name of the TalosCluster.</dd>
  <dt>`<version>`</dt>
  <dd>The new version, in the form `v1.2.3`.</dd>
</dl>

## Flags

<CliFlags cmd="upgrade" />

## What it does

1. The command reads the TalosCluster.
2. It examines the step. It refuses these steps and changes nothing:
   - A version that is not in the form `v1.2.3`.
   - A version that is older than the current one.
   - A Talos upgrade from a release that Talos does not support as a source.
   - A pair of Talos and Kubernetes versions that Talos does not support.
3. It writes the version into `spec.talosVersion` or `spec.kubernetesVersion`.
4. It waits for the rollout, at most the time of [`--wait`](cli:upgrade#--wait).
5. It prints the plan of the rollout and the command that approves it.

<dl>
  <dt>Talos upgrade</dt>
  <dd>The operator drains each node, upgrades it with the installer for that version and reboots it. Control planes go first.</dd>
  <dt>Kubernetes upgrade</dt>
  <dd>Each node gets the new kubelet and the new control plane images. Then kube-proxy follows.</dd>
</dl>

If the cluster already asks for the version, the command changes nothing and shows the rollout.
With `--wait 0`, the command does not wait for the rollout.

Upgrade Kubernetes.

```sh
pk-metal upgrade kubernetes lab v1.36.3
```

## Objects

| Object | Access | Purpose |
| --- | --- | --- |
| [](kind:TalosCluster) | get, patch | Writes the version. The patch carries the UID and the resource version of the object that the command read. |
| [](kind:TalosRollout) | list | Finds the rollout that the operator proposes for the version. |

If you keep the TalosCluster in git, change the version there. The command and git must not disagree.

## Exit status

<CliExit cmd="upgrade" />

The command gives code 1 if no rollout has a plan when the time of [`--wait`](cli:upgrade#--wait) ends. The version in the spec stays.
