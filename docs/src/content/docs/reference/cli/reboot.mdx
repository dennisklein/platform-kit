`pk-metal reboot` proposes a clean reboot of one Talos node as a [](kind:HostOperation).
Nothing changes until a person approves the operation. Your site decides if that can be you.

## Synopsis

<CliSynopsis cmd="reboot" />

<dl>
  <dt>`<node>`</dt>
  <dd>The name of the [](kind:TalosNode). It is also the name of the Kubernetes node.</dd>
</dl>

## Flags

<CliFlags cmd="reboot" />

`--grace-period` is at most 3600 seconds.

## What it does

1. The command asks the API server for your user name.
2. It reads the TalosNode and finds the [](kind:Host) that runs it.
3. It makes a HostOperation with the reason `Reboot` in the namespace `pk-metal`. You are the proposer.
4. The operation waits for approval. You can approve it yourself only if your site allows self-approval.

### The plan

| Step | Action | Effect |
| --- | --- | --- |
| 1 | [](act:Cordon) | Kubernetes schedules no new pods on the node. |
| 2 | [](act:Drain) | Evicts the pods, so that each PodDisruptionBudget holds. DaemonSet pods and static pods stay. |
| 3 | [](act:TalosReboot) | Reboots the node through Talos. With `--mode powercycle`, a cold power cycle follows. |
| 4 | [](act:WaitNodeReady) | Waits until the node is ready in Talos and in Kubernetes. |
| 5 | [](act:WaitEtcdHealthy) | Control plane only. Waits until etcd is healthy again. |
| 6 | [](act:Uncordon) | Kubernetes schedules pods on the node again. |

### Guards

<dl>
  <dt>Control plane</dt>
  <dd>The operator reboots it only while all other etcd members are healthy and no other control plane of the cluster is down. Until then, the approved operation waits with the block `ClusterDisruption`.</dd>
  <dt>Drain</dt>
  <dd>If a PodDisruptionBudget holds a pod, the drain waits for the time of [`--drain-timeout`](cli:reboot#--drain-timeout). Then the operation fails and the node stays cordoned.</dd>
  <dt>`emptyDir` data</dt>
  <dd>A pod with `emptyDir` data fails the drain, unless you give [`--delete-emptydir-data`](cli:reboot#--delete-emptydir-data). With the flag, the pods lose that data.</dd>
</dl>

## Examples

<Terminal
title="pk-metal reboot"
text={`
    $ pk-metal reboot cp-2
    proposed pk-metal/reboot-cp-2-m4q8z: a clean reboot of TalosNode cp-2 on host simhw2288v5000398 (6 steps).
    Approve it after reading the plan (another person must, if the site forbids self-approval): pk-metal approve pk-metal/reboot-cp-2-m4q8z
    It is a control plane of cluster lab: once approved, it waits until every other etcd member is healthy and no other control plane is down.
    To withdraw it: pk-metal abort --reason "<reason>" pk-metal/reboot-cp-2-m4q8z
`}
/>

Give the pods more time, and let the drain wait longer.

```sh
pk-metal reboot --drain-timeout 30m --grace-period 60 cp-2
```

Do a cold start, for example after a firmware change.

```sh
pk-metal reboot --mode powercycle --delete-emptydir-data w-1
```
