Conditions are the facts about an object. Each condition has a type, a status, a reason and a message.
This page lists each type and each reason. The text of the tables comes from the Go source.

## How to read a condition

```console
$ kubectl get mep ci-00398 -o json | jq '.status.conditions[] | select(.type == "Verified")'
{
  "type": "Verified",
  "status": "False",
  "reason": "SerialMismatch",
  "message": "asserted serial SIMHW2288V5000398 not among discovered [SIMHW2288V5000399]"
}
```

<dl>
  <dt>type</dt>
  <dd>The name of the fact. Find it in the tables of conditions.</dd>
  <dt>status</dt>
  <dd>True, False or Unknown. Unknown usually means that the work is in progress. An absent condition means that the operator did not examine the fact.</dd>
  <dt>reason</dt>
  <dd>One word for the cause. Find it in the tables of reasons. `status.blockedOn` and `pk-metal status` show the same word.</dd>
  <dt>message</dt>
  <dd>A sentence for a person. It often gives the command to run.</dd>
</dl>

The phase is a summary of the conditions. [](ref:phases) lists the rules, and [](concept:phases-and-conditions) explains the model.
Use [](cli:status) to see the reasons that need a person.

## Link to a condition or a reason

The anchor of a condition is its name in lower case. The anchor of a reason has the prefix `reason-`.
When the two groups have the same name, the anchor for `os.pk.io` has `os-` before the name.
