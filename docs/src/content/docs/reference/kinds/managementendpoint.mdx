A ManagementEndpoint is one BMC that the operator speaks to through Redfish.
The operator makes it from an Asset. You read it to see if the BMC answers and what it reports.

## At a glance

<dl class="pk-glance">

  <dt>Scope</dt>
  <dd>Cluster. Short name: `mep`.</dd>

## How it connects

The [](ctrl:asset) makes the endpoint and writes all of its spec.
The address comes from the [ledger](concept:ledger), the Secret from the Asset, and the TLS rule from the manager.
The [](ctrl:managementendpoint) opens a session, reads the facts and compares them with the Asset. It does not write to the BMC.
The [](ctrl:host) makes one Host for each entry in [`status.systems`](kind:ManagementEndpoint#status.systems).

An [](kind:EndpointProfile) selects endpoints by their labels. The [](ctrl:endpointconvergence) then configures the BMC and writes the condition `Configured`.
A [](kind:HostOperation) uses the endpoint to change the machine, for example with [](act:InsertMedia).
Use [](cli:status) to see all endpoints, or [](cli:check) to test one BMC without the operator.

## Lifecycle

<EndpointPhases />

1. The Asset controller makes the endpoint. The phase is Pending.
2. The operator opens a Redfish session. The phase is Connecting.
3. The operator reads the vendor, the model, the systems, the media slots and the firmware. The phase is Inventorying.
4. The operator compares the MAC address and the serial number with the Asset. The phase is Verifying.
5. If an EndpointProfile applies, the operator configures the BMC. The phase is Configuring.
6. All conditions agree. The phase is Ready.

The operator reads the BMC again each 5 minutes. The flag `--poll-interval` of the [manager](ctrl:manager) sets this time.

<PhaseTable kind="ManagementEndpoint" />

### How the operator verifies a BMC

<dl>
  <dt>MAC address</dt>
  <dd>If the BMC reports a MAC address and it is not `spec.bmcMac` of the Asset, `Verified` is False with the reason `MACMismatch`.</dd>
  <dt>Serial number</dt>
  <dd>The operator collects the board serial number of the chassis and the serial number of each system. If `spec.serial` of the Asset is one of them, `Verified` is True.</dd>
  <dt>No match</dt>
  <dd>`Verified` is False with the reason `SerialMismatch`. The phase is Mismatch.</dd>
  <dt>No data</dt>
  <dd>If the BMC reports no serial number, `Verified` is Unknown and the phase stays Verifying.</dd>
</dl>

## Status

<FieldTable kind="ManagementEndpoint" part="status" />

### Conditions

| Condition | True means | Effect on the phase |
| --- | --- | --- |
| `Reachable` | The BMC answers and the login works. | Unreachable when False |
| `Inventoried` | The operator has the facts of the BMC. | Inventorying until True |
| `Verified` | The MAC address and the serial number agree with the Asset. | Mismatch when False |
| `Configured` | The BMC has the configuration of its EndpointProfiles. Absent when no profile applies. | Configuring until True |
| `DeletionHeld` | A person deleted the endpoint, but a claim holds its machine. | None |

### Labels

The operator puts labels on each endpoint. An EndpointProfile selects endpoints with them.

| Label | Value |
| --- | --- |
| `metal.pk.io/vendor` | The vendor that the BMC reports. |
| `metal.pk.io/model` | The model that the BMC reports. |
| `metal.pk.io/vlan` | `spec.vlan` of the Asset. |

[](ref:labels-annotations) has all keys.

## Example

You do not write a ManagementEndpoint. Read it with `kubectl`:

```console
$ kubectl get mep -o wide
NAME       ADDRESS                        VENDOR   PHASE      BLOCKED          AGE
asset-07   https://[2001:db8:0:100::14]   Huawei   Ready                       3d
asset-08   https://[2001:db8:0:100::15]   Huawei   Mismatch   SerialMismatch   3d
```

## Find why an endpoint is not Ready

1. Read the phase and the column BLOCKED.

   ```sh
   kubectl get mep -o wide
   ```

2. Read the conditions of the endpoint. The message of the condition gives the cause.

   ```sh
   kubectl describe mep asset-08
   ```

3. Use the table to find the next step.

| Phase | Cause | Next step |
| --- | --- | --- |
| Unreachable | The address, the network, the login or the CA is wrong. | [](rb:bmc-unreachable) |
| Mismatch | The Asset or the ledger names a different machine. | [](rb:host-mismatch) |
| Configuring | A profile is in progress, or the operator cannot apply it. | Read the reason of `Configured` in [](kind:EndpointProfile). |

<Callout type="caution">
Do not correct a Mismatch on the endpoint. Correct the Asset or the ledger.
The operator stops all work on the machine until the facts agree.
</Callout>
