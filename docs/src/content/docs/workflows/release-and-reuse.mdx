When you delete a [](kind:HostClaim), the operator releases the machine.
A released machine never keeps its node. [](concept:release-and-wipe) explains the rules.

<ReleaseAndReuse />

<Callout type="warning">
Do not delete a HostClaim to remove a machine from the inventory.
The release wipes the system disk of the node. To stop management without a change, keep the claim.
</Callout>

## Steps

1. Delete the HostClaim, or delete its [](kind:TalosNode). [](cli:scale) can do it for you.
2. The [](ctrl:hostclaim) proposes one release [](kind:HostOperation).
3. If the node ran on this machine, the release waits for approval. Approve it with [](cli:approve).
4. If the node answers, the operation does these actions:
   1. [](act:Cordon) and [](act:Drain);
   2. on a control plane, [](act:EtcdForfeitLeadership) and [](act:EtcdLeave);
   3. [](act:TalosReset), which wipes the system disk;
   4. [](act:DeleteKubernetesNode).
5. If the node does not answer, the operation does [](act:EtcdRemoveMember) on a control plane and [](act:DeleteKubernetesNode).
6. Then [](act:PowerOff) and [](act:EjectMedia). The [](kind:Host) is `Available`.
7. If the Talos reset did not run, the Host has the condition `DiskWiped=False`. Wipe it with [](cli:wipe) and approve the wipe.

## Release rules

| Situation | Approval | Disk after the release |
| --- | --- | --- |
| The node ran on the machine, on record | Necessary | Wiped by Talos |
| The node does not answer | Necessary | Not wiped. The Host is marked. |
| No boot reached its check-in step | Not necessary | Not touched |
| The claim has approval Automatic | Not necessary | As above |
| A control plane leave makes etcd unsafe | Refused until you add `metal.pk.io/ack-etcd-risk` | - |

"On record" means the [hand-off record](kind:HostClaim#status.handOff) of the claim, or the check-in step of a boot.
It does not mean that the node answers at this moment.
