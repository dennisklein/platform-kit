An [](kind:EndpointProfile) can give the operator its own account on each BMC.
The operator then changes the password of that account on a schedule.
It keeps the password that works until the new one is proven.

<CredentialRotation />

## Steps

1. Write the factory credentials of the BMC into the Secret that the [](kind:Asset) names in `credentialsRef`.
2. Write an EndpointProfile with a [`credentials`](kind:EndpointProfile#spec.credentials) stanza: the account name and [`maxAge`](kind:EndpointProfile#spec.credentials.maxAge).
3. The [](ctrl:endpointconvergence) makes the account through the factory login.
4. When the managed Secret is older than `maxAge`, the controller rotates the password:
   1. it parks a new password beside the working one;
   2. it sets the new password on the BMC;
   3. it logs in with the new password to prove it;
   4. it promotes the new password and records the time.
5. Each BMC session uses the managed Secret, if it has a working password. If not, it uses the factory credentials.
6. Read the result in the `Configured` condition of the [](kind:ManagementEndpoint).

## The two accounts

<dl>
  <dt>Factory account</dt>
  <dd>The account from the Secret of the Asset. The operator does not change it. It is the way back in when the managed password stops working.</dd>
  <dt>Managed account</dt>
  <dd>The account that the operator makes and rotates. Its Secret is `endpoint-creds-<endpoint>` in the namespace of the operator.</dd>
  <dt>Candidate</dt>
  <dd>A new password under the keys `next-username` and `next-password`. It replaces the working password only after a login with it works.</dd>
</dl>

<Callout type="note">
If someone changes the managed password on the BMC, the operator sets it back through the factory account.
The Secret does not change.
</Callout>

## Other credentials

- Talos and Kubernetes admin credentials have a short lifetime, see [](concept:credentials).
- To change BMC credentials by hand, follow [](howto:rotate-bmc-credentials).
