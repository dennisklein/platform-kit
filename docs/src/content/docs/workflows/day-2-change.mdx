A change to a cluster in use goes to the machines one node at a time.
A [](kind:TalosRollout) holds the plan, a person approves it, and the operator makes one [](kind:HostOperation) for each node.

<Day2Change />

## Steps

1. Change the [](kind:TalosCluster) or a [](kind:TalosNode):
   - for a Talos upgrade, use [](cli:upgrade);
   - for a configuration change, edit the spec;
   - to reboot each node in turn, write a TalosRollout of kind `Reboot`.
2. The [](ctrl:rolloutproposer) compares the spec with the machines and proposes a rollout. See [](concept:rollouts) and [](concept:drift).
3. Read the plan with [](cli:rollout).
4. A person approves the [plan hash](kind:TalosRollout#status.planHash). If your site forbids self-approval, that is not the proposer.
5. The [](ctrl:talosrollout) runs the first node, then pauses.
6. Examine the node. Resume the rollout with [](cli:rollout).
7. The control planes go one at a time, the etcd leader last. Then the workers go.
8. Before each node, the rollout reads etcd and the Kubernetes nodes again.
9. The rollout is `Complete`.

## Rollout kinds

| Kind | Proposed by | Actions on each node | Reboot |
| --- | --- | --- | --- |
| `TalosUpgrade` | The operator, when a node runs another version | [](act:Drain), [](act:TalosUpgrade), [](act:WaitNodeReady), [](act:Uncordon) | Yes |
| `KubernetesUpgrade` | The operator, when the API server runs another version | [](act:TalosApplyConfig), [](act:WaitNodeReady) | Only if Talos needs it |
| `Config` | The operator, when a node drifts | [](act:TalosApplyConfig), [](act:WaitNodeReady) | Only if Talos needs it |
| `Reboot` | You | [](act:Drain), [](act:TalosReboot), [](act:WaitNodeReady), [](act:Uncordon) | Yes |

A control plane also gets [](act:WaitEtcdHealthy) before the uncordon.
A node that does not reboot is not drained.

## Control the rollout

| You want to | Command |
| --- | --- |
| See the plan | `pk-metal rollout show <rollout>` |
| Approve | `pk-metal rollout approve <rollout>` |
| Continue after the pause | `pk-metal rollout resume <rollout>` |
| Stop before the next node | `pk-metal rollout pause <rollout>` |
| Stop for all time | `pk-metal rollout abort <rollout>` |

<Callout type="caution">
Do not change the spec of the TalosCluster again while a rollout waits for approval.
The plan then differs, and the rollout ends with reason `PlanChanged`.
</Callout>
