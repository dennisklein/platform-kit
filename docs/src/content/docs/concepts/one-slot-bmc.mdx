A normal install needs two media: the installer and the configuration.
Some BMCs hold one medium only. For a blank machine behind such a BMC, the operator builds one installer for that node, with the configuration inside.

## Terms

<dl>
  <dt>Embedded installer</dt>
  <dd>A Talos installer ISO with the configuration of one node inside. Talos 1.12 or later reads it.</dd>
  <dt>imager</dt>
  <dd>The Talos tool that builds the ISO. It runs as a Job in the namespace `pk-metal`. It reads the configuration from a file, not from its arguments.</dd>
  <dt>Media store</dt>
  <dd>A volume of the operator that holds the built ISOs. The kustomize component `config/media-store` adds it.</dd>
  <dt>Digest</dt>
  <dd>The hash of the ISO. The [](kind:BootAsset) records it. The media service checks it each time a BMC downloads the file.</dd>
</dl>

## Why not send the configuration over the network

A Talos machine without a configuration accepts a configuration from each client that reaches it.
The configuration holds the keys and tokens of the cluster. So the operator always sends it out of band, through the BMC.

<Callout type="caution">
Treat the media store volume like the Secret storage of the cluster.
Each ISO holds a node configuration in plain text, readable only by the operator user.
</Callout>

## Lifecycle of an ISO

1. A new configuration, Talos version or schematic gives a new build.
2. The operator deletes the old ISO when the new one is ready.
3. All ISOs of a node go with its [](kind:TalosNode).
4. A machine that already runs Talos needs no embedded ISO. Its configuration goes into the one slot as a small ISO.
