A [](kind:TalosRollout) is one change to one cluster, for each node in sequence.
The operator writes the plan, a person approves its hash, and each node operation must agree with that hash.

## Terms

<dl>
  <dt>Plan</dt>
  <dd>Each node in order, the Host it runs on, what changes, whether it reboots, and the actions of its operation.</dd>
  <dt>Plan hash</dt>
  <dd>A hash of the cluster, the kind, the target, the drain settings and each plan step.</dd>
  <dt>Pause after the first node</dt>
  <dd>The rollout always stops after its first node. You cannot turn this off. `pk-metal rollout resume` continues.</dd>
  <dt>Health gate</dt>
  <dd>The checks before each node. etcd has a leader, and no member has an error or is a learner. Each control plane is a member, and each other Kubernetes node is Ready.</dd>
</dl>

## Rules

1. Until approval, the operator keeps the plan current, for example when a node joins.
2. After approval, the plan is frozen. If the current plan differs before the first node starts, the rollout ends with `PlanChanged`.
3. Only one approved rollout runs on a cluster at a time.
4. A failed or aborted rollout is not proposed again. Delete it to get a new proposal.
5. The approver must not be the proposer or the operator. The approval is write once.
6. While the operator holds the secrets bundle (`SecretsBundleHeld=True`), the operator proposes and plans no `Config` and no `KubernetesUpgrade` rollout. A config rendered then has the old CA. See [](howto:rotate-cluster-credentials).
7. A `KubernetesUpgrade` moves one minor at a time. The plan refuses a skipped minor, also when someone changed the spec without [](cli:upgrade).

## Sequence

| Group | How many at a time |
| --- | --- |
| Control planes | One. The etcd leader goes last. |
| kube-proxy (Kubernetes upgrade only) | After the control planes |
| Workers | `spec.maxUnavailableWorkers`, default 1 |
