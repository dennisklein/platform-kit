Each object has conditions. A condition is one fact with a status, a reason and a message.
The phase is one word that summarizes the conditions. Read the conditions to know why something waits.

## Terms

<dl>
  <dt>Condition</dt>
  <dd>A fact with a type (for example `Verified`), a status (`True`, `False` or `Unknown`), a reason and a message in plain words.</dd>
  <dt>Reason</dt>
  <dd>One CamelCase word that a script can compare, for example `SerialMismatch`.</dd>
  <dt>Phase</dt>
  <dd>A summary of the conditions. The package `internal/phase` derives it again on each pass. It has no memory of the previous phase.</dd>
  <dt>blockedOn</dt>
  <dd>The reason of the condition that holds the object now. [](cli:status) shows it in the BLOCKED column.</dd>
</dl>

## Rules

1. A controller decides only on conditions. It never reads a phase.
2. Only the stamp functions in `internal/phase` write `phase` and `blockedOn`. A test fails on any other write.
3. The derivation is a list in order of precedence. Hard stops come first, for example `Unreachable` and `Mismatch`.
