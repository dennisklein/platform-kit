You do not write Talos machine configs. You write a [](kind:TalosCluster) for the shared part and a [](kind:TalosNode) for each machine.
The operator renders the config of each node into a Secret.

## Terms

<dl>
  <dt>Machine config</dt>
  <dd>The full configuration of one Talos node. It holds the keys of the cluster.</dd>
  <dt>Patch</dt>
  <dd>A part of a Talos config that you add on the TalosCluster or the TalosNode, for example `ResolverConfig`.</dd>
  <dt>schematic</dt>
  <dd>The kernel arguments and system extensions of the installer image. The image factory builds the image from it.</dd>
  <dt>Rendered for</dt>
  <dd>The Talos version that the operator renders a config for. Usually this is the version of the cluster. A node that runs an older version that the renderer supports keeps that version until a TalosUpgrade moves it.</dd>
</dl>

## Rules

1. Each config is a new Secret, named by its digest. The operator never changes a Secret in place. See [](concept:drift).
2. A running node does not get a new config by itself. A `Config` rollout applies it, see [](concept:rollouts).
3. If the Talos and Kubernetes versions cannot go together, `Rendered` is `False` with `UnsupportedVersionPair`. The last good config stays.
4. The operator refuses a TalosNode without an install disk selector.
5. The patches of the TalosCluster apply to each node. A document that Talos allows on control planes only, for example `KubeAuditPolicyConfig`, goes to the control planes only. In the patches of a worker TalosNode, such a document stops the render.
