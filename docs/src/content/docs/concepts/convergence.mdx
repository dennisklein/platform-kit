A profile selects machines by label and says what they must have.
The convergence controller merges the profiles for each Host, compares the result with the machine, and proposes a [](kind:HostOperation) for the difference.

## Terms

<dl>
  <dt>Profile</dt>
  <dd>A class of desired state: [](kind:BiosProfile), [](kind:FirmwareProfile) or [](kind:EndpointProfile).</dd>
  <dt>Layer</dt>
  <dd>The precedence of a profile. A higher layer overrides a lower one. Two profiles on the same layer that disagree are a conflict, and the operator holds the Host.</dd>
  <dt>BiosSchema</dt>
  <dd>The attribute registry that the BMC reports. The operator checks each desired attribute against it. See [](kind:BiosSchema).</dd>
  <dt>Plan hash</dt>
  <dd>The hash of a proposed change. The same hash never gives a second operation.</dd>
</dl>

## Rules

1. Firmware converges before BIOS, because the BIOS schema depends on the firmware.
2. The operation carries the attributes. A later edit of the profile cannot change an approved operation.
3. On a machine that runs a node, the operator wraps the change. It drains the node, reboots it through Talos with a power cycle and waits for the node.
4. A control plane also waits for a healthy etcd before and after.
5. The operator proposes no change on a machine that it runs on, see [](concept:self-protection).

## Conditions on the Host

| Condition | True means |
| --- | --- |
| `FirmwareConverged` | The BMC firmware agrees with the FirmwareProfile. |
| `SystemFirmwareConverged` | The BIOS, NIC and RAID firmware agree. |
| `BiosConverged` | The BIOS attributes agree with the BiosSettings. |
