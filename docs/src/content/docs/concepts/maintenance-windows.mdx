## Terms

<dl>
  <dt>Covered machine</dt>
  <dd>A machine that `spec.hostSelector` or `spec.clusters` selects. Either match is enough.</dd>
  <dt>Open</dt>
  <dd>The time inside a weekly or a one-time window, in `spec.timeZone`. Weekly windows keep the wall clock time across a daylight saving change.</dd>
  <dt>ignore-window</dt>
  <dd>The operation annotation `metal.pk.io/ignore-window`. Its value is your reason. The operation then starts outside the windows. An empty value does not count.</dd>
</dl>

## Rules

1. An approved operation on a covered machine waits until one of its windows is open.
2. When a window opens, the waiting operations start. Nobody has to be awake.
3. A step that runs is never stopped when the window closes.
4. A machine that no window covers is not held.
5. New installs (reason `Provisioning`) are not held.
6. A window that the operator cannot read is `Valid=False` and never opens. A mistake holds work back.
7. A rollout that reaches a node outside its windows waits between nodes.

## Where you see it

- `blockedOn: OutsideMaintenanceWindow` in [](cli:status). It does not count as "needs a person".
- `kubectl get maintenancewindows` shows OPEN and NEXT CHANGE.
- The metric `pk_metal_operation_blocked{reason="OutsideMaintenanceWindow"}`.
