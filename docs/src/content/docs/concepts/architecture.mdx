It reads the objects that you write and changes the machines through their BMCs.

## Parts

<dl>
  <dt>Management cluster</dt>
  <dd>The Kubernetes cluster that runs the operator. It holds all state as API objects. First a kind cluster, later the Talos cluster that the operator built, see [](concept:pivot-model).</dd>
  <dt>Manager</dt>
  <dd>The one process that runs all controllers. One replica holds the leader lease.</dd>
  <dt>BMC</dt>
  <dd>The controller on the main board of a machine. The operator uses Redfish to read it, to switch the power and to mount virtual media.</dd>
  <dt>Media service</dt>
  <dd>An HTTPS server in the manager. A BMC downloads the installer and the node configuration from it with a one-time grant.</dd>
  <dt>Talos node</dt>
  <dd>A machine that runs Talos Linux. It has no shell and no SSH. The operator uses the Talos API.</dd>
  <dt>Relay</dt>
  <dd>An optional forwarder for day 0, when your workstation cannot reach the BMCs. See [](concept:relay).</dd>
</dl>

## Principles

1. You write what must be true. The operator writes what it finds. See [](concept:assert-vs-observe).
2. A person approves each change to a machine. See [](concept:approval).
3. The operator boots from virtual media, not from PXE. See [](concept:virtual-media-boot).
4. The operator does not take down the cluster that it runs on. See [](concept:self-protection).
