On day 0 no cluster exists. [](cli:boot) runs on a workstation, but the workstation often cannot reach the BMC network.
[](cli:relay) runs on a host that can. It forwards the traffic. TLS does not stop at the relay.

## Terms

<dl>
  <dt>Front</dt>
  <dd>The address where BMCs download boot media.</dd>
  <dt>Tunnel</dt>
  <dd>The control port of the relay. It stays on loopback. You reach it with `ssh -L`.</dd>
  <dt>Relay secret</dt>
  <dd>A shared secret of at least 32 characters. Each line on the tunnel carries an HMAC of the secret, a fresh nonce, the verb and its argument.</dd>
</dl>

## Why the secret

The BMCs do not check the certificate of the media server.
A party that holds the control connection could read the grant, get the node configuration or serve its own ISO.
The HMAC proves who connects. A line without a valid HMAC gets `ERR unauthenticated`.
The secret does not encrypt the tunnel, so the tunnel stays on loopback.

## Rules

1. The relay writes a new secret file only if none exists. It never replaces a file.
2. [](cli:boot) only reads a secret. It never makes one.
3. The operator does not use the relay today. It is for day 0.
