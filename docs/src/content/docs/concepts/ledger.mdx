The ledger is the operator copy of your BMC address reservations.
An [](kind:Asset) gets a [](kind:ManagementEndpoint) only when its BMC MAC address is in the ledger.

## Format

A flat YAML map, one line for each BMC:

```yaml
"0c:c4:7a:12:34:56": https://192.0.2.21
"0C-C4-7A-12-34-57": https://[2001:db8::22]
```

## Terms

<dl>
  <dt>Ledger file</dt>
  <dd>The file that the manager reads with `--ledger`. In a cluster it comes from the ConfigMap `pk-metal-ledger` in the namespace `pk-metal`.</dd>
  <dt>Materialized</dt>
  <dd>The Asset condition that says whether the operator found the address and wrote the endpoint.</dd>
</dl>

## Rules

1. The operator writes MAC keys in lower case with colons. You can write them in each case, with `:` or `-`.
2. The operator skips and reports a line that it cannot use. It does not stop the other machines.
3. The manager reads the ledger when it starts. A changed ConfigMap from kustomize restarts the manager.

| Reason on the Asset | Meaning |
| --- | --- |
| `NoBMCMac` | The Asset has no `spec.bmcMac`. |
| `NoLedgerEntry` | The MAC address is not in the ledger. |
| `LedgerEntryInvalid` | The line for the MAC was skipped. The message says why. |
| `MaterializeConflict` | An endpoint with this name belongs to another Asset. |
