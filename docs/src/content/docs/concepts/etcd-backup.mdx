A snapshot holds each Secret of a cluster. So the operator encrypts it before it leaves the operator, with public keys only.
Only a person with a private key can decrypt it, on that person's own machine.

## Terms

<dl>
  <dt>Sink</dt>
  <dd>Where snapshots go: an S3 bucket, or a PersistentVolumeClaim of the operator.</dd>
  <dt>age recipient</dt>
  <dd>A public key `age1…` in the policy. Name at least two, for example two persons or one key in a safe.</dd>
  <dt>Verified</dt>
  <dd>The operator read the ciphertext back and its hash agrees. The plaintext was a valid bbolt database. Only a Verified snapshot can be restored.</dd>
  <dt>BackedUp</dt>
  <dd>The policy condition. True while a Verified snapshot is newer than two intervals.</dd>
</dl>

## Rules

1. A snapshot needs no approval. It reads etcd and changes no machine.
2. Retention removes old snapshots, but never the newest Verified snapshot.
3. The operator refuses a PVC sink for the cluster that it runs on, with `SinkRefused`. The cluster takes that volume with it when it fails.
4. The operator never restores by itself. A restore is approved operations, see [](flow:disaster-recovery).
5. The operator never bootstraps a cluster two times.

<Callout type="warning">
Delete a decrypted snapshot when you no longer need it.
It holds each Secret of the cluster in plain text.
</Callout>
