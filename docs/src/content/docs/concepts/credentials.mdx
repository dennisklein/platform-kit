A certificate that the cluster CA signed stays valid until it expires. Only a CA rotation revokes it.
So the operator gives the credentials that it publishes a short lifetime, and issues new ones before they expire.

## Terms

<dl>
  <dt>TTL</dt>
  <dd>[`spec.credentials.ttl`](kind:TalosCluster#spec.credentials.ttl). How long a published credential is valid. The default is 24 hours. The API refuses more than 720 hours (30 days).</dd>
  <dt>credentialsExpireAt</dt>
  <dd>[`status.credentialsExpireAt`](kind:TalosCluster#status.credentialsExpireAt). When the first published credential expires. Copy credentials out again before this time.</dd>
  <dt>Reader talosconfig</dt>
  <dd>With `spec.credentials.readerTalosconfig: true`, the operator also publishes `<cluster>-talosconfig-reader` with the role `os:reader`. Use it to monitor the cluster.</dd>
  <dt>Secrets bundle</dt>
  <dd>The CAs and tokens of the cluster, in `spec.secretsRef`. The operator keeps its own copy, `<cluster>-bundle-applied`.</dd>
</dl>

## Rules

1. If you make the TTL shorter, the operator replaces older credentials at once.
2. If the bundle in `spec.secretsRef` changes, the operator continues with its copy. `SecretsBundleHeld` is True.
3. The operator does not rotate CAs. Rotate them with `talosctl`.
4. Delete `<cluster>-bundle-applied` after the rotation.

<Callout type="caution">
Do not change the secrets bundle of a running cluster without a CA rotation on each node first.
The machines trust only the CAs of their install.
</Callout>
