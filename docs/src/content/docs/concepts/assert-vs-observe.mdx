Each fact has one author. You assert facts in objects that you keep in git.
The operator observes facts and writes them in its own objects and in each `status`.

## Terms

<dl>
  <dt>Assertion</dt>
  <dd>A fact that you write: the serial number of a machine, the install disk, the Talos version.</dd>
  <dt>Observation</dt>
  <dd>A fact that the operator reads from a BMC, a node or etcd, and writes in a status.</dd>
  <dt>Spec</dt>
  <dd>The part of an object that holds assertions. On a [](kind:Host) the operator writes the spec too, from the claim.</dd>
  <dt>Status</dt>
  <dd>The part of an object that holds observations. Only the operator writes it.</dd>
</dl>

## When they disagree

The operator does not guess which side is correct.
If the serial number in the Asset is not the serial number that the BMC reports, the operator stops for that machine.
See [](concept:identity) and [](rb:host-mismatch).

## Why it helps

- Your git repository holds only assertions. You can apply it again at each time.
- The status tells what is true now, not what someone wished.
- A change made by hand shows as drift, not as a new truth. See [](concept:drift).
