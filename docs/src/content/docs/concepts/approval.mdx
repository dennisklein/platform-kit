Nothing that disrupts a machine happens before a person approves it.
The operator only proposes. A second person reads the plan and approves it. Then the operator runs it.

## Terms

<dl>
  <dt>Proposal</dt>
  <dd>A [](kind:HostOperation) or a [](kind:TalosRollout) that waits in `AwaitingApproval`. It names its proposer in `spec.proposedBy`.</dd>
  <dt>Plan</dt>
  <dd>The list of actions, fixed when the operator proposes. A changed plan is a new proposal with a new name.</dd>
  <dt>Approver</dt>
  <dd>A person with the ClusterRole `pk-metal-approver`, other than the proposer.</dd>
  <dt>Hold</dt>
  <dd>The annotation `metal.pk.io/hold` on a claim. While it is there, the operator proposes nothing for the claim.</dd>
  <dt>Automatic approval</dt>
  <dd>A claim setting, `spec.provisioning.approval: Automatic`. Only an admin can set it.</dd>
</dl>

## What needs approval

| Change | Approval |
| --- | --- |
| Install, BIOS change, firmware, reboot, wipe | Yes, one per operation |
| Release of a machine that ran its node | Yes |
| Talos or Kubernetes upgrade, configuration change | Yes, one for the rollout plan |
| Read the BMC, take an etcd snapshot, dry run of a configuration | No |
| Rotation of BMC credentials, NTP servers of a BMC | No, the [](kind:EndpointProfile) is the approval |
| New TLS identity of a BMC | No, the EndpointProfile is the approval. The push restarts the BMC and drops its virtual media, so it waits until the approved operations behind that BMC end. |

Only a member of the admin group can create or change an EndpointProfile. See [](ref:admission-policies).

## How many approvals

| Task | Approvals |
| --- | --- |
| Install 40 machines | 40, one for each install. With `provisioning.approval: Automatic` on the claims: none. |
| Upgrade Talos or Kubernetes on a cluster of 40 nodes | 1, for the rollout plan. |
| Change a configuration on a cluster of 40 nodes | 1, for the rollout plan. |
| Change the BIOS settings of 40 machines | 40, one for each machine. |
| Replace one machine ([](cli:replace)) | 2: the release of the old machine, then the install on the new machine. |

## Safeguards

- [](cli:approve) approves only the plan that it printed. If the operation changed in the meantime, nothing is approved.
- The approval names the uid and the resourceVersion that you read, so the API server refuses it if the object changed.
- A gate after the approval can still hold the start, see [](concept:maintenance-windows) and [](concept:cluster-guard).
