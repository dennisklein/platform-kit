The operator never changes a config Secret in place. Each new config gets a new Secret, named after the node and the digest of the content.
A dry run on each node then tells whether the machine runs the current config.

## Terms

<dl>
  <dt>Content-addressed Secret</dt>
  <dd>A config Secret named `machineconfig-<node>-<digest>`. Its name changes when its content changes.</dd>
  <dt>Dry run</dt>
  <dd>A question to Talos: what changes if this config is applied? Talos answers and changes nothing.</dd>
  <dt>Drift</dt>
  <dd>The machine does not run the config that the operator renders. [`status.drift`](kind:TalosNode#status.drift) gives the number of lines, the changed keys and whether a reboot is necessary. It never holds values.</dd>
</dl>

## When the dry run runs

| Situation | Interval |
| --- | --- |
| Normal | 10 minutes |
| A rollout runs on the cluster | 30 seconds |

## ConfigInSync

| Status | Reason | Meaning |
| --- | --- | --- |
| `True` | `InSync` | The machine runs what the operator renders. |
| `False` | `ConfigDrift` | It does not. The operator proposes a `Config` rollout. |
| `Unknown` | `DriftUnknown` | The dry run failed. The message says why. |

If Talos does not say whether a change needs a reboot, the operator assumes that it does.

## Which Secrets stay

- The current config.
- The config that the node last applied.
- Configs that an unfinished operation or rollout names.

The operator deletes the others.

## Why it helps

- An edit to a TalosCluster or TalosNode reaches the machines through a rollout.
- A change made by hand with `talosctl` shows as drift, and the rollout undoes it.
