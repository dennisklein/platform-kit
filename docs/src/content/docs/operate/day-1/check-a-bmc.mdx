## Goal

Make sure that one BMC answers, and find its serial number, media slots and NIC MAC addresses.

## Before you start

- You have the `pk-metal` binary on a workstation that can reach the BMC on TCP 443. [](howto:install-operator) shows how to build it.
- You have the BMC user name and password. Usually these are the factory values.
- The machine can be on or off. The two commands read only. They change nothing on the machine.

## Steps

<Steps>

1. Put the BMC password in the environment. The commands read it only from there.

   ```sh
   read -rs PK_METAL_BMC_PASSWORD && export PK_METAL_BMC_PASSWORD
   ```

2. Check the BMC. If the BMC certificate comes from your own CA, give the CA file with `--bmc-ca`. Use `--insecure` only if the BMC has a self-signed certificate.

   ```sh
   pk-metal check --user admin --insecure https://192.0.2.21
   ```

   ```text
   manager:  Huawei fw 6.72
   media:    CD             dialect=vmm-control
   media:    USBStick       dialect=none
   system:   1 serial=SIMHW2288V5000391 power=On
   check:    OK (read-only)
   ```

   This is the output for the simulated Huawei iBMC.

3. Read the inventory into a file.

   ```sh
   pk-metal inventory --user admin --insecure --node sim-0001 https://192.0.2.21 > sim-0001.yaml
   ```

   The file has the BMC MAC, the media slots, the serial number, the NICs and the drives. If the BMC has more than one system, add `--system <id>`. The command then describes that system.

4. Write down the serial number and the BMC MAC. You need them for the [](kind:Asset).

5. Write down the MAC of the NIC that the node uses, and the serial of the install disk. You need them for the [](kind:TalosNode).

</Steps>

## Read the result

<dl>
  <dt>`media:` lines</dt>
  <dd>One line for each virtual media slot. Count the lines that do not show `dialect=none`. One such line means a [](term:one-slot-bmc). The example above has two lines, but only one usable slot.</dd>
  <dt>`dialect=none`</dt>
  <dd>The slot cannot mount an image. The operator does not use it.</dd>
  <dt>One usable slot</dt>
  <dd>Add the media store to your overlay before the install. See [One-slot BMCs](howto:install-operator#one-slot-bmcs) and [](concept:one-slot-bmc).</dd>
  <dt>More than one `system:` line</dt>
  <dd>The BMC controls more than one machine. [](cli:inventory) needs `--system`, and your [](kind:HostClaim) must set `spec.systemRef`.</dd>
  <dt>`serial=-`</dt>
  <dd>The system has no serial. The inventory file then shows the board serial of the chassis.</dd>
</dl>

<Callout type="note">
The inventory file has the MAC addresses of your site. Do not publish it.
</Callout>

## Verify

The last line of [](cli:check) is `check:    OK (read-only)`.

## If it fails

| What you see | Go to |
| --- | --- |
| `check failed:` with a timeout or a TLS error | [](rb:bmc-unreachable) |
| `401` or `403` in the error | Check the user name and the password. |
| No `media:` line | [](rb:media-slot-busy) |
| The check passes with `--insecure`, but the endpoint is `Unreachable` later | The manager checks the certificate. See [BMC certificates](howto:install-operator#bmc-certificates). |
