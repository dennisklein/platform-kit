## Goal

Make the first Talos cluster of a site from a workstation, when no management cluster exists.
Later, you can [](howto:pivot) the operator onto this cluster.

## Before you start

- You have the [](kind:TalosCluster) and [](kind:TalosNode) files of the cluster in one directory. See [](howto:define-a-cluster).
- You have the secrets bundle from `talosctl gen secrets`.
- Your workstation, or a host that runs [](cli:relay), can reach the BMCs. The BMCs can reach it back.
- You have the BMC password of each machine.
- Each BMC has two virtual media slots. [](cli:check) shows the slots: two lines that are not `dialect=none`.
- You have the URL of a Talos installer ISO that reads its configuration from a medium. Step 1 makes it.

<Callout type="caution">
[](cli:boot) mounts the configuration only. It does not mount the installer.
A blank machine boots the installer from a second slot, and the installer reads the configuration from the medium of [](cli:boot).
A BMC with one slot cannot hold the two media. For such a machine, start the operator in kind and let it build an embedded installer. See [](concept:one-slot-bmc).
</Callout>

<Callout type="note">
The usual way is different. Start kind on a workstation, install the operator there, and let it install the machines.
[](tut:lab-first-cluster) shows that way. Use this page only when you cannot run kind.
</Callout>

## Steps

<Steps>

1. Get the installer ISO URL. The installer must have the kernel argument `talos.config=metal-iso`, so that it reads the configuration medium.
   Register a schematic with this argument at the Talos Image Factory. Use the Talos version of your cluster.

   ```sh
   printf 'customization:\n  extraKernelArgs:\n    - talos.config=metal-iso\n' > schematic.yaml
   id=$(curl -sf --data-binary @schematic.yaml https://factory.talos.dev/schematics | jq -r .id)
   echo "https://factory.talos.dev/image/$id/v1.14.6/metal-amd64.iso"
   ```

2. Render the machine configs. This touches no machine. Write the output to a directory outside your git repository: the files hold the cluster secrets.

   ```sh
   pk-metal render --dir manifests --secrets secrets.yaml --out ~/prod-clusterconfig
   ```

   The directory has one `<node>.yaml` for each node, a `talosconfig` and a `kubeconfig`.
   The `talosconfig` and the `kubeconfig` are valid for 24 hours (`--credentials-ttl`, at most 720 hours). Nobody can revoke them before that time, except with a CA rotation.
   If the secrets bundle is encrypted, decrypt it to standard input and give `--secrets -`. Then no plain copy goes to the disk.

3. Put the BMC password of the first machine in the environment.

   ```sh
   read -rs PK_METAL_BMC_PASSWORD && export PK_METAL_BMC_PASSWORD
   ```

4. Mount the installer ISO on the first slot of the BMC. Use the web console of the BMC, and the URL from step 1.
   The BMC must reach the Image Factory. If it cannot, download the ISO and serve it from a host that the BMC can reach.

5. Find the other slot. Note its id.

   ```sh
   pk-metal check https://192.0.2.21
   ```

6. Boot the first machine into its config. `--media` is the slot from step 5. `--listen` is an address on your workstation that the BMC can reach.

   ```sh
   pk-metal boot --config ~/prod-clusterconfig/cp-1.yaml --node cp-1 --media 2 --listen 192.0.2.5:8443 https://192.0.2.21
   ```

   The command shows its steps. Without `--yes`, it refuses to reset a machine that is on.
   The machine starts the installer, which installs Talos with the config to the disk.

7. Examine the console of the machine. It must start the installer and not an operating system that is on the disk.

8. Do step 3 to step 7 for each other machine.

9. Start the cluster. The command bootstraps etcd one time and waits until each node is `Ready`.

   ```sh
   pk-metal bootstrap --dir manifests --secrets secrets.yaml
   ```

   The last line is `bootstrap: OK: prod is bootstrapped and its nodes are ready`.

</Steps>

<Callout type="warning">
Do not run [](cli:boot) against a machine that runs a system you must keep.
If the machine is on, the command does a hard reset. Running work stops without a clean shutdown.
</Callout>

## If the BMCs cannot reach your workstation

Run [](cli:relay) on a host on the BMC network. Then give `--relay` to [](cli:boot) in place of `--listen`.
The relay and boot share a secret. [](concept:relay) explains why.

```sh
ssh -L 9443:127.0.0.1:9443 relay-host
pk-metal boot --relay 127.0.0.1:9443 --relay-secret-file ./relay.secret \
  --config ~/prod-clusterconfig/cp-1.yaml --node cp-1 https://192.0.2.21
```

## Verify

```sh
kubectl --kubeconfig ~/prod-clusterconfig/kubeconfig get nodes
```

Each node is `Ready`.

## If it fails

| What you see | Fix |
| --- | --- |
| `boot` times out and the image was not read | The BMC cannot reach `--listen`. Use `--relay`, or open the port. |
| The machine starts in Talos maintenance mode and waits | The installer has no `talos.config=metal-iso`. Do step 1 again. |
| The machine starts the old system from its disk | The boot override did not start the installer. Mount the installer on the slot that the machine starts first. |
| `boot` ejected the installer | `boot` used the installer slot. Give the other slot with `--media`. |
| `bootstrap` waits for a node | Read the serial console of the node. See [](rb:node-not-ready). |
| `bootstrap` reports data in etcd | A member has old etcd data. See [](rb:bootstrap-refused). |
