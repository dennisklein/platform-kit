## Symptoms

<dl>
  <dt>[](kind:TalosCluster)</dt>
  <dd>`status.credentialsExpireAt` comes near, and does not move forward.</dd>
  <dt>Alert</dt>
  <dd>`PkMetalCredentialsExpiring`: it has less than one sixth of its lifetime.</dd>
</dl>

## Impact

When the credential expires, people and tools that use the published kubeconfig or talosconfig cannot connect. The cluster continues to run.

## Diagnose

The operator mints a new credential when it has one third of its lifetime. At one sixth, the renewal is late. See [](concept:credentials).

<Steps>

1. Read the expiry and the conditions of the cluster.

   ```sh
   kubectl describe taloscluster prod
   ```

2. Read the manager log for the cluster.

   ```sh
   kubectl -n pk-metal logs deploy/pk-metal-manager | grep prod
   ```

</Steps>

## Fix

| Cause | Fix |
| --- | --- |
| The manager does not run | See [](rb:management-cluster-lost). |
| `SecretsUnavailable`: the secrets bundle Secret is missing | Apply the Secret from git again. |
| The log shows that a Secret write failed | Check the manager role in the credentials namespace. |

## Verify

`status.credentialsExpireAt` moves forward. The alert resolves.
