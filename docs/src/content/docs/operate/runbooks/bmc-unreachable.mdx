## Symptoms

<dl>
  <dt>Endpoint phase</dt>
  <dd>`Unreachable` or `Connecting` for a long time. `Reachable=False`.</dd>
  <dt>Asset</dt>
  <dd>`Materialized=False` with `NoLedgerEntry`, `NoBMCMac` or `LedgerEntryInvalid`. No endpoint exists.</dd>
  <dt>Operation</dt>
  <dd>`BLOCKED` shows `NoReachablePath`.</dd>
  <dt>Alert</dt>
  <dd>`PkMetalBMCUnreachable`.</dd>
</dl>

## Impact

The operator cannot read or change the machine. Steps that go through the Talos API still work. A running node is not affected.

## Diagnose

<Steps>

1. Read the endpoint phase and its `Reachable` condition.

   ```sh
   kubectl get managementendpoints
   kubectl describe managementendpoint sim-0001
   ```

   The `Reachable` message holds the error of the last probe.

2. If no endpoint exists, read the Asset condition.

   ```sh
   kubectl describe asset sim-0001
   ```

   The `Materialized` condition names the ledger problem.

3. From a workstation on the BMC network, check the BMC. Talos nodes have no shell.

   ```sh
   pk-metal check https://192.0.2.21
   ```

   Do not add `--insecure` to find the cause. A certificate error is a cause.

</Steps>

## Fix

| Cause | Fix |
| --- | --- |
| `NoLedgerEntry` | Add the BMC MAC to the ledger. Apply the overlay. The manager restarts. |
| `LedgerEntryInvalid` | The line is not an `https` URL, or the MAC is in the ledger two times. Correct it. |
| Timeout | Check the network path on TCP 443. See [](howto:network-checklist). |
| A proxy is set | Add the BMC network to `NO_PROXY` of the manager. See [](howto:behind-a-proxy). |
| `x509` or `certificate` in the message | The manager does not trust the BMC certificate. Give the CA that signed it to the manager (`--bmc-ca-secret`, see [](ctrl:manager) and [BMC certificates](howto:install-operator#bmc-certificates)), or replace the BMC certificate. |
| `TLSKeyChanged` | The BMC shows a key that is not pinned. Find out why, then approve the key. See [Trust the BMC certificate](kind:ManagementEndpoint#trust-the-bmc-certificate). Do not approve a key that you cannot explain. |
| `TLSKeyNotPinned` | The endpoint has no pinned key yet. The next observation pins it. If it stays, the BMC does not answer on TLS. |
| `401` in the message | The credentials are wrong. Check the Secret that `credentialsRef` names. |
| The BMC hangs | Reset the BMC from its web console, or remove power from the BMC. |

## Verify

The endpoint phase is `Ready`. `pk_metal_bmc_reachable` is `1`.

## If this does not work

Follow [](howto:collect-diagnostics). Include the manager log.
