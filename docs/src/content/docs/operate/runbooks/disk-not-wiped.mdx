## Symptoms

<dl>
  <dt>[](kind:Host)</dt>
  <dd>`DiskWiped=False` with `InstalledNodeRemains`. The annotation `metal.pk.io/disk-not-wiped` names the cluster and the node.</dd>
  <dt>[](kind:HostClaim)</dt>
  <dd>`BLOCKED` shows `DiskNotWiped`.</dd>
</dl>

## Impact

The operator does not install on the machine and does not power it on. If the machine booted from its disk, it would join a cluster where it does not belong.

## Diagnose

```sh
kubectl describe host simhw2288v5000399
```

The message names the node that the disk may hold.

## Fix

<Steps>

1. Ask for the wipe.

   ```sh
   pk-metal wipe simhw2288v5000399
   ```

2. Approve the proposed operation.

   ```sh
   pk-metal approve
   ```

</Steps>

If you know that the disk is empty, remove the mark yourself. In the same request, set `metal.pk.io/wipe-waived` to your user name and the reason. The [admission policy](ref:admission-policies#guard-lift) `guard-lift` refuses a removal without it. The audit log names the waiver when an install starts on the machine.

```sh
kubectl annotate host simhw2288v5000399 metal.pk.io/disk-not-wiped- \
  metal.pk.io/wipe-waived="$(kubectl auth whoami -o jsonpath='{.status.userInfo.username}'): disk replaced"
```

<Callout type="warning">
Do not remove the mark if you are not sure. An old node with valid credentials can join its cluster again.
</Callout>

## Verify

`DiskWiped=True`. A waiting claim proposes its install.
