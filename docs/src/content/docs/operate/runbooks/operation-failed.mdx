## Symptoms

<dl>
  <dt>[](kind:HostOperation) phase</dt>
  <dd>`Failed`. The condition `Executed=False` has the reason `StepFailed`.</dd>
  <dt>Claim</dt>
  <dd>`BLOCKED` shows `OperationFailed` or `ReleaseFailed`.</dd>
  <dt>Host</dt>
  <dd>`BiosConverged=False` or `FirmwareConverged=False` with `OperationFailed` or `ConvergenceFailed`.</dd>
  <dt>Alert</dt>
  <dd>`PkMetalOperationFailed`.</dd>
</dl>

## Impact

The operation stopped at the failed step. Steps before it stay done. The operator proposes nothing for the plan until a person acts.

## Diagnose

<Steps>

1. Read the note line under the `OPERATION` table.

   ```sh
   pk-metal status
   ```

2. Find the step that failed and its message.

   ```sh
   kubectl -n pk-metal describe hostoperation provision-simhw2288v5000397-0f3c9a1e
   ```

3. Find the cause from the step.

</Steps>

| Step | Common cause | Go to |
| --- | --- | --- |
| [](act:InsertMedia) | The BMC cannot download the image | [](rb:media-slot-busy) |
| [](act:AwaitCheckIn), [](act:WaitNodeReady) | The node did not come up in time | [](rb:node-not-ready) |
| [](act:Drain) | A PodDisruptionBudget or an `emptyDir` pod | [](rb:drain-stuck) |
| [](act:TalosUpgrade) | "did not take": Talos went back to the old image | Read the node console. |
| [](act:FlashFirmware), [](act:ApplyBios) | The BMC refused the change, or reported success and did not change (`ConvergenceFailed`) | Check the firmware image and the vendor notes. |
| [](act:WaitEtcdHealthy) | etcd did not become healthy | [](rb:etcd-unhealthy) |

## Fix

<Steps>

1. Correct the cause.

2. Retry the operation. If the operator made it, the operator proposes the same plan again.

   ```sh
   pk-metal retry pk-metal/provision-simhw2288v5000397-0f3c9a1e
   ```

3. Approve the new proposal.

   ```sh
   pk-metal approve
   ```

</Steps>

<Callout type="note">
The retry deletes the failed operation. Its lines in the operator audit log stay. To keep the full record, save it first: `kubectl -n pk-metal get hostoperation <name> -o yaml`. See [](ref:audit-trail).
</Callout>

<Callout type="note">
`pk-metal retry` only deletes an operation that a person made, for example with [](cli:reboot). Make it again yourself.
An operation of a rollout ends the rollout. Follow [](rb:rollout-paused).
</Callout>

<Callout type="note">
For an `Aborted` operation, the last step lists what the abort undid and what it could not undo. Retry it in the same way.
</Callout>

## Verify

The new operation is `Succeeded`.

## If this does not work

To stop new proposals while you look, hold the claim with [](cli:hold). Then follow [](howto:collect-diagnostics).
