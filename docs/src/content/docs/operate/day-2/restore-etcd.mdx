## Goal

Bring back the etcd of a cluster with the minimum data loss.

## Before you start

- A person with `pk-metal-approver` can approve. That is you, if your site allows self-approval. If not, it is a second person. See [](howto:approval-permissions).
- For a lost majority: you have an age identity that can decrypt the snapshot, and a verified snapshot exists.
- The operator never restores and never bootstraps again by itself.

## Find the case

```sh
pk-metal restore plan prod
```

The command asks each control plane about its etcd. It changes nothing.

| What the plan sees | Case |
| --- | --- |
| Each member healthy | Nothing to do |
| One member stopped or has errors; the others keep a majority | [One member lost](#one-member-lost) |
| No control plane lists members, or most do not answer | [Majority lost](#majority-lost) |
| The operator's own cluster has no etcd | [](rb:management-cluster-lost) |

## One member lost

No snapshot is necessary. The broken member leaves, its data is wiped, and it joins again.

<Steps>

1. Propose the repair.

   ```sh
   pk-metal restore plan prod --propose
   ```

   The command makes `prod-etcd-replace-<node>` with [](act:EtcdRemoveMember), [](act:TalosReset) and [](act:WaitEtcdHealthy).

2. Approve it. If your site forbids self-approval, ask a second person to approve it.

   ```sh
   pk-metal approve pk-metal/prod-etcd-replace-cp-2
   ```

3. Monitor it until it is `Succeeded`.

   ```sh
   kubectl -n pk-metal get hostoperation prod-etcd-replace-cp-2 -w
   ```

</Steps>

Repair one member at a time. With three control planes, a second lost member is a lost majority.

<Steps>

1. List the snapshots.

   ```sh
   pk-metal backup list prod
   ```

2. Propose the plan. Name the snapshot and the control plane, or take the defaults.

   ```sh
   pk-metal restore plan prod --snapshot prod-offsite-20261124-060000 --node cp-1 --propose
   ```

3. Approve each reset operation, or ask a second person if your site forbids self-approval.

   ```sh
   pk-metal approve pk-metal/prod-etcd-reset-cp-2
   ```

4. Approve the recover operation, or ask a second person if your site forbids self-approval.

   ```sh
   pk-metal approve pk-metal/prod-etcd-recover-cp-1
   ```

5. Upload the snapshot. For a `pvc` sink, [copy the snapshot](#copy-a-snapshot-from-a-pvc-sink) first. Then add `--from-file <file.age>`.

   ```sh
   pk-metal restore upload pk-metal/prod-etcd-recover-cp-1 --identity ~/.config/age/keys.txt
   ```

6. Monitor the operations.

   ```sh
   kubectl -n pk-metal get hostoperation -l os.pk.io/etcd-restore=prod
   ```

</Steps>

<Callout type="warning">
You lose all data written after the snapshot. Read the snapshot time in the plan before you approve.
</Callout>

## Copy a snapshot from a `pvc` sink

The manager image has no shell. Use a small pod that mounts the backup volume.
The pod runs as the user of the manager, which owns the files.
It meets the `restricted` Pod Security level of the namespace.

<Steps>

1. Find the node of the manager. A volume that attaches to one node only needs the pod on that node.

   ```sh
   node=$(kubectl -n pk-metal get pod -l app.kubernetes.io/name=pk-metal,app.kubernetes.io/component=manager \
     -o jsonpath='{.items[0].spec.nodeName}')
   ```

2. Start the reader pod on that node.

   ```sh
   kubectl apply -f - <<YAML
   apiVersion: v1
   kind: Pod
   metadata:
     name: etcd-backup-reader
     namespace: pk-metal
   spec:
     nodeName: $node
     restartPolicy: Never
     securityContext:
       runAsNonRoot: true
       runAsUser: 65532
       runAsGroup: 65532
       seccompProfile: { type: RuntimeDefault }
     containers:
       - name: reader
         image: busybox:1.37
         command: ["sleep", "3600"]
         securityContext:
           allowPrivilegeEscalation: false
           capabilities: { drop: ["ALL"] }
         volumeMounts:
           - { name: backups, mountPath: /backups, readOnly: true }
     volumes:
       - name: backups
         persistentVolumeClaim: { claimName: pk-metal-etcd-backups, readOnly: true }
   YAML
   kubectl -n pk-metal wait --for=condition=Ready pod/etcd-backup-reader
   ```

3. Copy the snapshot. Its path is `<cluster>/<snapshot>.db.age`, as `status.key` of the [](kind:EtcdSnapshot) shows.

   ```sh
   kubectl -n pk-metal exec etcd-backup-reader -- ls -l /backups/prod
   kubectl -n pk-metal exec etcd-backup-reader -- cat /backups/prod/prod-daily-20261124-060000.db.age > prod.db.age
   ```

4. Delete the pod.

   ```sh
   kubectl -n pk-metal delete pod etcd-backup-reader
   ```

</Steps>

Give the file to `pk-metal restore upload --from-file`, or decrypt it with `pk-metal backup decrypt --in prod.db.age`.

## Verify

- `kubectl get taloscluster prod` shows `Bootstrapped=True` and `Available=True`.
- `pk-metal restore plan prod` reports that each member is healthy.

## If it fails

| What you see | Go to |
| --- | --- |
| `etcdRecover` waits for a control plane that never answers | Remove its TalosNode, or replace the machine. Then plan again. |
| `restore upload` stops on a hash mismatch | The file is not the approved snapshot. Use the approved one. |
| `Bootstrapped=False` with another reason | [](rb:bootstrap-refused) |
