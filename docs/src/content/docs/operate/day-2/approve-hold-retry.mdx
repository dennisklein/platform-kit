## Goal

Control each [](kind:HostOperation): run it, stop new proposals, run a failed one again, or stop a running one.

## Before you start

- You have the ClusterRole `pk-metal-approver`. It lets you patch HostOperations.
- If you proposed the operation, your site allows self-approval (`selfApproval`, see [](howto:approval-permissions)). If it does not, another person must approve.

## Approve

<Steps>

1. List the operations that wait for a person.

   ```sh
   pk-metal approve
   ```

2. Approve one. The command shows each step in plain words. Type `y`.

   ```sh
   pk-metal approve pk-metal/provision-simhw2288v5000397-0f3c9a1e
   ```

   The operation goes to `Running`, or it waits for its [](kind:MaintenanceWindow).

3. To approve several operations, give several names. The command shows the plan of each one, and it asks about each one.

   ```sh
   pk-metal approve pk-metal/provision-simhw2288v5000397-0f3c9a1e pk-metal/provision-simhw2288v5000398-5e6f7a8b
   ```

</Steps>

No command approves all operations that wait. Each approval is an answer to one plan. See [](cli:approve).

The command reads the operation again after your answer. If the plan changed, it approves nothing.

## Hold a claim

A hold stops new proposals for one [](kind:HostClaim). Nothing on the machine changes.

<Steps>

1. Hold the claim. Give the reason.

   ```sh
   pk-metal hold --reason "waiting for new disk" default/w-1
   ```

   [](cli:status) shows `(on hold)` for the claim.

2. When you are ready, remove the hold.

   ```sh
   pk-metal unhold default/w-1
   ```

</Steps>

## Retry a failed operation

<Steps>

1. Read why the operation failed.

   ```sh
   kubectl -n pk-metal describe hostoperation provision-simhw2288v5000397-0f3c9a1e
   ```

2. Correct the cause.

3. Retry the operation.

   ```sh
   pk-metal retry pk-metal/provision-simhw2288v5000397-0f3c9a1e
   ```

   The operator proposes the same plan again. The new operation waits for approval.

</Steps>

## Abort a running operation

<Steps>

1. Abort the operation. Give the reason.

   ```sh
   pk-metal abort --reason "wrong machine" pk-metal/reboot-w-1-x7k2p
   ```

2. Monitor the operation until its phase is `Aborted`.

   ```sh
   kubectl -n pk-metal get hostoperation reboot-w-1-x7k2p -w
   ```

</Steps>

The operation stops before its next step. Then the operator ejects the media, clears the boot override and removes its cordon.
A reboot, an applied config or an upgrade stays as it is.

<Callout type="caution">
Do not delete a running operation to stop it. A deletion stops it too, but it undoes nothing.
</Callout>

## Verify

- `pk-metal status` shows the new phase.
- The `APPROVED` column shows your user name.
