## Goal

Keep verified, encrypted etcd snapshots of a cluster away from its machines.

## Before you start

- You have `age-keygen`.
- For an S3 sink: a bucket and a key that can write, read, list and delete there.
- A snapshot reads etcd only. It needs no approval.

## Steps

<Steps>

1. Each person who may restore makes an age key pair. Keep `keys.txt` like an SSH private key.

   ```sh
   age-keygen -o ~/.config/age/keys.txt
   ```

2. Show the public key. It starts with `age1`.

   ```sh
   age-keygen -y ~/.config/age/keys.txt
   ```

3. Put the S3 key into a Secret in `pk-metal`.

   ```sh
   kubectl -n pk-metal create secret generic etcd-backup-s3 \
     --from-literal=accessKeyID=AKEXAMPLE --from-literal=secretAccessKey="$S3_SECRET"
   ```

4. Write an [](kind:EtcdBackupPolicy). Name at least two recipients.

   ```yaml title="prod-offsite.yaml"
   apiVersion: os.pk.io/v1alpha1
   kind: EtcdBackupPolicy
   metadata:
     name: prod-offsite
   spec:
     clusterRef:
       name: prod
     interval: 6h
     retention:
       count: 28
     sink:
       s3:
         endpoint: https://s3.example.org
         bucket: etcd-backups
         prefix: metal/
         pathStyle: true
         credentialsSecretRef:
           name: etcd-backup-s3
     encryption:
       ageRecipients:
         - age1qexampleperson0000000000000000000000000000000000000000000
         - age1qexampleoffline000000000000000000000000000000000000000000
   ```

5. Apply it.

   ```sh
   kubectl apply -f prod-offsite.yaml
   ```

6. Take the first snapshot now. The command waits until the operator verifies the snapshot.

   ```sh
   pk-metal backup now prod-offsite
   ```

7. Decrypt it on your workstation, as a test. Without `-o`, the command writes no plain file.

   ```sh
   pk-metal backup decrypt prod-offsite-20261124-060000 --identity ~/.config/age/keys.txt
   ```

</Steps>

<Callout type="warning">
Use an `s3` sink for the cluster that runs the operator. The operator refuses a `pvc` sink there, because you lose that volume with the etcd that it backs up.
</Callout>

## Verify

```sh
pk-metal backup list prod
kubectl get etcdbackuppolicy prod-offsite
```

The policy shows `BackedUp=True` and `0` failures.
