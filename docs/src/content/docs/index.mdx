## How a machine gets installed

The operator uses Redfish and virtual media. It does not use PXE, TFTP or DHCP.
Step through the install of one machine. Each box links to its reference page.

<Provision start={1} />

## Three rules

1. You write what must be true. The operator writes what it finds. Read [](concept:assert-vs-observe).
2. The operator does nothing that disrupts a machine before a person approves it. Read [](concept:approval).
3. Conditions are the facts. The phase is a summary for people. Read [](concept:phases-and-conditions).

## After the install

The operator also does the day-2 work: Talos and Kubernetes upgrades, etcd backup and restore, node changes, BIOS and firmware, and maintenance windows.
Each change is a proposal that a person approves. Read [the overview](/start/overview/#what-it-does-after-the-install).

## Status and requirements

- **Status.** No release yet. The API is `v1alpha1`. The automatic tests use simulated BMCs. Read [](ref:status).
- **Hardware.** x86-64 servers in UEFI mode, with a Redfish BMC that can mount virtual media. Read [](ref:hardware).
- **Versions.** Talos v1.14.0 or later. Read [](ref:versions).
- **The lab.** A Linux workstation with KVM, Docker Engine and 12 GiB of free memory. Read [](lab:page/prerequisites).
- **Real hardware.** Start with [](tut:first-real-server). System administrators: read [For system administrators](/start/for-sysadmins/).
